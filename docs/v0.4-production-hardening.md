# v0.4 Production Hardening: 交付文档

日期:2026-08-16 · 状态:完成

v0.4 把 v0.3 的信任边界落到运营面:审计可证明、凭据会过期、控制器不因
单任务中毒而停摆、资源有界、镜像内容被钉住。五个切片全部落地并通过
构建/单元/集成/race 验证。

## 1. 事务内审计账簿(ADR-014)

- `audit_events`(迁移 000012):per-tenant 单调 `seq` + `prev_hash`/`chain_hash`
  (长度前缀规范编码,SHA-256;首事件锚定 genesis 常量,头部截断可检测);
  数据库级 append-only 触发器拒绝 UPDATE/DELETE。
- 每次内核决策在**同一事务**内追加:task 生命周期/准入/调度/取消、
  agent version 发布、memory 写入与墓碑、approval 请求/决定/过期、
  tool call 决策、attempt 获取/转移、checkpoint、完成/恢复、取消确认。
  并发追加由 per-tenant 事务性 advisory lock 串行化,seq 无空洞。
- 控制面 API(OpenAPI 同步):`GET /v1/audit`(游标分页)、
  `GET /v1/audit/verify`(全链校验,报首个断裂 seq)、
  `GET /v1/audit/export`(`-audit-signing-key` 配置时 ed25519 签名归档)。
- 测试:链完整性、篡改精确断链(含数据库级 UPDATE/DELETE 拒绝)、并发
  追加密度、分页、签名导出验签;安全套件 DB 同步纳入 audit 表清理。

## 2. 审计投影到 OpenSearch(append-only)

- `AuditProjector` 消费 `agentos.events.audit.>`:`AuditRecorded` 事件按
  seq 幂等索引(含 prevHash/chainHash,供合规检索);无墓碑路径。
- `agentos-projector` 现可同时跑 `memory` 与 `audit` 两个投影
  (`-projection memory,audit`,独立索引与 durable consumer)。
- 真实 E2E 烟测:task.queued → 出箱 → JetStream → agentos-audit 可检索;
  memory 投影同步回归。

## 3. OpenBao 动态数据库凭据(ADR-015)

- `bao.DynamicBroker`:`database/creds/<role>` 签发 username/password 作为
  scoped handle;租约跟踪 + janitor 续租/到期吊销;`Close` 吊销全部租约
  ——**凭据永不过网关进程而存活**;关闭后签发 fail-closed。
- gateway:`-bao-dynamic-role` 启用动态 broker(janitor 30s 循环,退出时
  吊销);`deploy/dev/openbao-init.ps1` 幂等配置 database engine(dev-db,
  5m TTL,仅 SELECT)。
- 真实 E2E:签发 → 用动态凭据连接 PostgreSQL 并查询 → Close 吊销 →
  被吊销凭据连接被 PostgreSQL 拒绝(密码认证失败)。

## 4. 控制器硬化(review 遗留)

- **逐任务错误隔离**(O4):admission/scheduler/recovery 控制器中,单任务
  失败不再阻塞整个批次——非可重试错误记录日志、释放 claim、继续;
  可重试事务仍中止批次走有界退避。三类控制器各配中毒任务测试。
- **分路由预算**(N9):读 5s / 写 10s(`WithRequestTimeouts` 可调),
  `/events` 免预算,`/audit/export` 用写预算;超预算 → `504 REQUEST_TIMEOUT`。
- **SSE 并发上限**(O5):`WithMaxSSESubscribers`(默认 64),超出 →
  `503 STREAM_CAPACITY_EXCEEDED`。
- **MCP 并发上限**(O8):`NewServerWithConcurrencyLimit`(默认 16),超出 503。

## 5. OCI 镜像 digest 钉住(ADR-010 补全)

- `workload.Spec.Image`(ref + `sha256:<64hex>` digest,校验/规范形/相等);
  `agentversion.Spec.Image` 版本级钉住,发布时校验。
- 准入:`RUNTIME_IMAGE_INVALID / RUNTIME_IMAGE_REQUIRED /
  RUNTIME_IMAGE_MISMATCH`——版本钉了镜像,任务必须钉同一个。
- OCI worker:只运行 spec 钉住的引用(裸 ref 或 canonical ref@digest 两种
  配置形态均可),不匹配/畸形/缺失分别以 `image_pin_mismatch` /
  `image_pin_invalid` / `image_required` 在**执行前**失败 attempt。
- 测试:镜像校验/规范形、策略 admit/require/mismatch/malformed、
  worker 三种失败路径 + 两种匹配形态(bufconn 全协议)。

## 6. 明确边界(文档化)

- **工件配额/GC**(O7):单工件大小上限已有;聚合配额与保留/GC 策略需与
  审计留存权衡,记入下一 slice。
- **decimal 账本**(D5):float64 相对误差 ~1e-16 不影响硬停;
  Go 侧引入 decimal 类型是独立增量,记入下一 slice。
- **并行 Reconcile**(P1):控制器当前按批次串行事务;按 pool/tenant 分区
  并行是明确的下一增量。
- **Firecracker/microVM**:仍为文档化边界(见
  [firecracker-microvm-boundary.md](firecracker-microvm-boundary.md)),
  其验收前置条件(OCI 加固清单在 Linux CI 验证等)未变。
