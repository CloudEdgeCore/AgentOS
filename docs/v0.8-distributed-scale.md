## 1. 租户一致性调度分片(ADR-016)

- 决策:控制器实例声明 `(shard-index, shard-count)`,只领取
  `md5(tenant_id) % count == index` 的任务;claim 时在 SQL 内计算
  (md5 前缀 32 位,跨 PG 版本稳定,`store.TenantShard` 为 Go 侧同源
  实现,测试交叉断言 SQL 与 Go 一致)。
- 语义不变:claim 独占、fencing token、TTL 让渡、O6 退避、outbox、lease
  全部不动;分片只收窄"哪个实例可以尝试领取"。现有双实例回归测试
  继续全绿。
- 配置:`cmd/agentos-controller` 新增 `-shard-index/-shard-count`(默认
  0 = 不分片,向后兼容);准入与调度共用同一分片(同一租户的整条流水线
  归一个实例);部署不变量:所有实例分片配置一致,不一致时任务停在
  QUEUED/ADMITTED(失败可见)。
- 测试:`TestShardFilterMatchesGoMapping`(SQL 与 Go 映射逐租户交叉
  校验、每租户恰好被一个分片领取、非法配置拒绝)、
  `TestShardedControllerInstancesOwnDisjointTenants`(两个分片实例各自
  只处理自己租户的任务,总体 exact-once)。

## 2. 多租户压力模型

`TestMultiTenantStressQuotaIsolationAndRecovery`:8 个租户(配额
1000/2000/无限制三档)并行提交混合负载(正常 / 准入后取消 /
worker 抖动-租约丢失-恢复重试),真实 Postgres + 默认控制器循环。
断言全部是精确计数:

- 准入数按 reservation 语义确定:tenant-0 恰 10 个(1000/100)、tenant-1
  恰 20 个(2000/100)、无配额租户全部 40 个;超额任务全部以
  `TENANT_QUOTA_EXCEEDED` 拒绝;
- 取消子集:恰等于"已准入的 cancel 类任务"数,每条一条 TaskCancelled
  outbox 事件;
- 抖动子集:租约 100ms 过期 → recovery 接管(新 fencing token)→ 全部
  重试成功,不丢任务;
- 结算后窗口:tenant-0 consumed=1000、reserved=0(完成即释放);
- wave-2 隔离:tenant-0 新提交全部拒绝、无配额 tenant-2 全部准入;
- 出站箱单 dispatcher 排空:published == total、unpublished == 0、
  fencing 拒绝 == 0;
- 无残留 claim、无活跃租约、无 QUEUED/RUNNING 遗留。

## 3. 容量基线(10k / 100k)

`TestControlPlanePipelineCapacityBaseline`(独立 schema,可重复,断言全
为计数精确性)。开发机(单 Postgres)实测:

| 规模 | 端到端 | 入队 | 准入 | 调度 | 完成 |
|---|---|---|---|---|---|
| 1,000 | ~40 tasks/s | 255/s | 215/s | 209/s | 85/s |
| 3,000 | ~37 tasks/s | 247/s | 190/s | 188/s | 78/s |
| 10,000 | ~36 tasks/s | 244/s | 187/s | 182/s | 79/s |
| 30,000 | ~37 tasks/s | 251/s | 194/s | 188/s | 82/s |
| 100,000 | ~39 tasks/s | 246/s | 190/s | 187/s | 90/s |

**吞吐在 1k→100k 全程恒定(36–40 tasks/s),无退化**;完成阶段(16 路
并发事务链)是当前瓶颈(~80–90/s),入队/准入/调度均 ~190–250/s。
墙钟:10k ~4.6 分钟、30k ~13.3 分钟、100k ~43 分钟(测试需
`-timeout 90m`;drain 截止随规模缩放,避免大基线被固定墙钟误杀)。

**中间件决策(ADR-017)**:1k→100k 五档证据显示单 Postgres 控制面无瓶颈
——吞吐恒定(36–40 tasks/s)、无锁等待放大、无 outbox lag(排空 0
fencing)。结论:**v1.0 前不引入 Kafka/ClickHouse**。ADR-017 全文见
`docs/adr/017-middleware-evidence.md`。

## 4. 配额 reservation 强化

- 迁移 `000015`:窗口行增加 `reserved_*` 四维计数;`task_budget_ledgers`
  增加 `quota_reserved_window_start`(记录预留所在窗口)。
- **准入即预留**:`DecideAdmission` 在窗口行锁下检查
  `consumed + reserved + ceiling ≤ limit`,通过则 `reserved += ceiling`
  (窗口行不存在时先建行,保证并发准入在同一行锁上串行)。v0.6 的
  "同瞬并发准入按 ceiling 之和有界超窗"限制**被关闭**:突发不再超窗。
- **终态释放**:任务到达终态(SUCCEEDED / FAILED / CANCELLED)时,按
  ledger 记录的窗口精确归还预留(跨窗口任务释放到原窗口);释放点覆盖
  CompleteRun、TransitionTask、RequestTaskCancellation(无运行分支)、
  AcknowledgeCancellation、RecoverExpiredAttempt(取消与超限两分支)。
- **语义**:预留是保守上界(在途任务的 ceiling 计入占用,结算不释放,
  终态才释放);`GET /v1/quota` 增加 `reserved` 字段。
- **结算期硬停评估(结论:不进 v1.0)**:结算来自运行中任务的真实用量,
  结算期拒绝会打断在途执行;每任务预算已经是结算期硬停(ledger
  exhausted),租户窗口的硬停面与 reservation 叠加收益有限,记入 v1.0
  后的候选项。
- 测试:门测试重写为 reservation 语义(突发关闭、结算不释放、终态释放
  重开空间、窗口滚动)、记账测试增加 reserved 断言、控制器单测
  (reserved 驱动拒绝)、压力测试以 reservation 语义为基准。

## 6. 边界(与 v0.7 相同,未变化)

- SPIRE / Linux CI 真机腿(runsc/containerd)/ Firecracker KVM 前置不变;
- 分片 hot-tenant 边界:单一热点租户收敛到一个分片;pool 维度分片
  (placement 派生键)为下一增量;
- reservation 语义:跨窗口任务在完成时释放到原窗口;永不到达终态的
  任务保留预留直到窗口滚动(视为已承诺容量)。
