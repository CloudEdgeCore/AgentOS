# v0.5 Runtime Hardening & Scale-Readiness: 交付文档

日期:2026-08-16 · 状态:完成

v0.5 把 OCI/gVisor 加固清单(runtime-provider-oci-gvisor.md §4)的代码面落地,
并完成评审遗留的规模化项:容器类资源限额全链路强制、孤儿容器回收、
stdout 有界落盘、镜像签名与 SBOM、工件配额与保留 GC、并行 Reconcile。
全部通过构建/单元/集成/race 验证。

## 1. 容器类资源限额全链路强制(§4.1)

- `workload.Placement.workspaceBytes`:沙箱工作区(临时文件系统)进入 spec。
- Admission:`Limits.ContainerClasses`(oci/microvm)——该类任务零值
  cpuMillis/memoryMiB/workspaceBytes 一律拒绝
  (`CONTAINER_CPU_REQUIRED` / `CONTAINER_MEMORY_REQUIRED` /
  `CONTAINER_WORKSPACE_REQUIRED`);其他类不受影响。
- OCI worker:spec 声明的限额覆盖操作员默认值并独立强制
  (`resource_limits_required` 在执行前失败);runsc executor 把限额编码为
  ctr `--cpu-quota`(微秒)/`--memory`(字节)参数(Linux,命令面待 Linux CI 复核)。
- 测试:Admission 逐类校验、worker 缺失限额拒绝、spec 驱动限额直达 executor。

## 2. 孤儿容器回收 + stdout 有界落盘(§4.3/§4.4)

- `reapTargets` + active 容器注册表:Prepare 前清理 `agentos-*` 前缀且不属于
  存活执行的孤儿容器;并发 Prepare 互不误删。
- `OutputSpooler` 契约 + `SpoolCap`(4 MiB)有界 spool:容器 stdout/stderr
  tee 进 Artifact Store(worker 实现),截断探测区分"恰好满"与"溢出";
  结果文档记录 `stdoutRef` / `stdoutTruncated`。
- 测试:spool 上限/截断/恰好满/无 spooler 丢弃、reaper 过滤、结果文档携带
  stdout 引用。

## 3. cosign 风格镜像签名 + CycloneDX SBOM(ADR-010 收尾)

- `agentpkg`:`SignImage`/`VerifyImageSignature`(命名空间载荷
  `agentos.image/v1`,镜像签名与 manifest 签名不可互用);manifest 携带
  `signedImageDigest` + `imageSignature`,`Verify` fail-closed 一并验签。
- CycloneDX 1.5 SBOM:`GenerateSBOM`/`VerifySBOM`/`SBOMDigest`。
- CLI:`agentos-pkg sign -image-digest`(嵌入并签名镜像钉)、`sbom`(生成并
  打印待钉 digest)、`verify-sbom`。
- 测试:镜像签名 round-trip/篡改/未知键/manifest 签名重放拒绝/半绑定拒绝、
  SBOM 生成/验签/篡改/非 CycloneDX;CLI 全流程烟测。

## 4. 工件配额与保留 GC(O7)

- `Filesystem` store:per-tenant 与 total 字节配额(0=不限),提交前强制;
  内容寻址去重不重复计费;staging 文件不计入用量。
- `GarbageCollect(retention)`:TTL 式清理过期工件,staging 文件与新鲜工件
  不受影响;两个 runtime cmd 增加 `-artifact-gc-retention` 启动期 GC。
- 测试:租户/总量配额、去重不重计、GC 删除过期保留新鲜、staging 跳过。

## 5. 并行 Reconcile(P1)+ 多实例控制面

- admission/scheduler/recovery 控制器:批次内按 claim/candidate 并行处理
  (默认 4 个 worker,`WithParallelism(1)` 回退串行);可重试错误仍中止批次
  走有界退避,逐任务隔离语义不变。
- 测试:8 claim 慢提交批次实测并发重叠(峰值 >= 2),串行模式峰值恒为 1。
- **多实例控制面**:`task_controller_claims` 的 owner + fencing token 语义
  (ClaimTasks 抢占抬高 token、过期自动让渡)使多个控制器实例可安全并存;
  v0.4 的 `TestControllerClaimFencingAndOutboxOwnership` 已锁定该行为。
  跨实例分片(按 pool/tenant 分区)是下一增量。

## 6. 明确边界(文档化)

- **SPIRE/workload attestation**(ADR-011 投影):本阶段仍是"CA 签发 + 信任束
  分发"模型;SPIRE agent/workload API 接入保持投影。
- **runsc/containerd 真机腿**:§1 的 ctr 命令面、seccomp/capability drop/
  只读 rootfs 等必须接入 Linux CI(containerd + runsc 主机)逐条验证;
  本机(Windows)只验证了协议与纯逻辑面。
- **Firecracker/microVM**:仍为文档化边界;验收前置(本清单 Linux CI 验证、
  KVM 可用、版本矩阵钉死)未变。
- **引用感知 GC**:当前 GC 是 TTL 式;按 checkpoint/result 引用存活分析的
  精确 GC 需与审计留存权衡,记入下一 slice。

## 运行清单(增量)

```powershell
# 任务 spec 必须为 oci 类声明显式限额:
# {"placement":{"runtimeClasses":["oci"],"cpuMillis":250,"memoryMiB":512,
#   "workspaceBytes":1048576,"llmConcurrency":1}}
# CI 打包流水线:
go run ./cmd/agentos-pkg sbom -manifest manifest.json -out sbom.json   # 钉入 manifest.sbom
go run ./cmd/agentos-pkg sign -manifest manifest.json -key-id ci-builder-1 `
  -private-key <b64> -image-digest sha256:<64hex> -out package.json
# worker 启动期 GC:
go run ./cmd/agentos-runtime-oci ... -artifact-gc-retention 168h
```
