# v0.3 Security Negative Test Suite

`internal/security` is the negative test suite of the Secure Runtime: it
attacks each security boundary with the exact abuse the boundary exists to
stop, and asserts the rejection. Positive tests prove features work; this
suite proves the boundaries hold.

## 1. Secret leak

`TestSecretHandleNeverLeaks` runs a tool whose executor deliberately echoes
its scoped credential handle into the output — the worst-case tool behavior.
The gateway must contain it:

- the invocation result must not contain the handle (or any handle-shaped
  fragment) after sanitization;
- the durable side-effect receipt must not carry it;
- the stored tool call record must not carry it.

## 2. Approval binding

`TestApprovalCannotAuthorizeDifferentInvocation` approves one invocation and
then attempts to reuse the decision:

- identical invocation + approval → executes (control);
- different canonical arguments → `BINDING_MISMATCH`, nothing runs;
- different resource → `BINDING_MISMATCH`;
- a rejected approval → `REJECTED`, nothing runs.

The executor call counter proves mismatched approvals never reach execution.

## 3. Tenant escape

- `TestTenantEscapeRejectedAtGatewayBoundary`: the Tool Gateway rejects
  `ListTools` and `InvokeTool` claiming a foreign tenant with
  `PermissionDenied` before the invoker is consulted (the invoker call
  counter stays at zero).
- `TestTenantEscapeRejectedAtRuntimeControlBoundary`: the Runtime Protocol
  rejects a cross-tenant poll.
- `TestTenantEscapeRejectedOnRealStore` (integration): the same boundary
  against real PostgreSQL.

## 4. Fencing replay

- `TestFencingReplayRejectedAtProtocolBoundary`: a stale fencing token maps
  to `PermissionDenied` for heartbeat, checkpoint and transition RPCs.
- `TestFencingReplayRejectedAfterTakeover` (integration, real PostgreSQL):
  a worker acquires an attempt, its lease lapses, recovery takes the attempt
  over and bumps the fencing token; the old worker then replays its stale
  token on heartbeat, checkpoint, transition and assignment reads — every
  call is rejected `PermissionDenied`, and the checkpoints table proves no
  durable state was written under the stale token.

## Running

Unit scenarios run in the normal suite:

```
go test ./internal/security/...
```

The integration scenarios need the dev database:

```
AGENTOS_TEST_DATABASE_URL=postgres://agentos:agentos-dev-only@127.0.0.1:55432/agentos?sslmode=disable \
    go test -tags integration ./internal/security/...
```
