# v0.1 收尾切片:OIDC 身份、可观测栈、Memory 检索、OCI CI 接入

日期:2026-08-16 · 状态:完成

补齐技术基线 §19 v0.1 Kernel Slice 的剩余四项。

## 1. 基本 OIDC 身份(基线 §11.2)

- `internal/control/auth/oidc.go`:`OIDCMiddleware(issuer, clientID, tenantClaim)` —
  go-oidc 发现 + JWKS 缓存 + RS256/ES256 验证;`sub` → Principal.Subject,
  租户 claim(默认 `tenant`,可配置)→ Principal.TenantID。
- `cmd/agentos-control`:`-dev-tenant`(loopback 静态身份)与
  `-oidc-issuer/-oidc-client-id/-oidc-tenant-claim`(验证身份)**二选一**;
  生产形态不再依赖静态身份。
- 测试:本地 fake OIDC provider(RSA + discovery + JWKS + 签发),覆盖
  有效 token、自定义 claim、缺失 Bearer、伪造签名、错误 audience、
  过期、错误 issuer、缺失租户 claim。

## 2. OpenTelemetry 参考栈(基线 §15)

- `internal/platform/otel`:`Init()` 按标准环境变量
  (`OTEL_EXPORTER_OTLP_ENDPOINT` / `OTEL_SERVICE_NAME` / `OTEL_SDK_DISABLED`)
  配置 OTLP trace/metric/log 导出;无端点时全程 no-op,二进制可无条件初始化。
- 埋点:控制面 HTTP(otelhttp)、全部 fenced gRPC 边界(otelgrpc stats
  handler,经 `grpcx.ServerOptions/ClientOptions`)、全部 7 个 main 进程。
- 日志:有界异步 slog→OTel 桥(Handle 永不阻塞;溢出丢最旧),控制台直写
  stderr。**调试中发现并修复一个真实死锁**:slog 默认 handler 经旧 `log`
  包的全局互斥写 stderr,与 OTel exporter 内部日志同锁互死——控制台 handler
  改为直写 `os.Stderr` 后消除(goroutine dump 定位)。
- 参考栈:`docker compose --profile observability up -d` 起
  otel-collector(OTLP→Tempo/Prometheus/Loki)+ Grafana(预置三个数据源)。
- 端到端验证:control 请求 → Tempo 收到 trace、Loki 收到结构化日志
  (`service.name` 标签),Prometheus 抓取 collector。

## 3. Memory Canonical Store(FTS + pgvector,ADR-009)

- 迁移 000010:`memory_records`(tenant/namespace/key 唯一、sensitivity、
  provenance、retention、tombstone、resource_version、来源 task/run/attempt 外键),
  `vector(384)` + `pg_trgm` 扩展装进 **pg_catalog**(schema 隔离的
  conformance/load 迁移也能解析类型与运算符类);`search` 生成列 FTS +
  GIN,`gin_trgm_ops` 支撑中文/子串;默认精确向量搜索(基线 §13.2)。
- `internal/kernel/store/memory.go` + postgres:`PutMemory`(同
  (tenant,namespace,key) 同文档幂等重放、异文档=修正新版本、复活墓碑)、
  `GetMemory`(删除意图可见)、`SearchMemory`(FTS+trigram+余弦混合排序,
  租户/敏感级过滤先于打分)、`TombstoneMemory`(CAS 软删除)。
- `internal/kernel/memory`:Embedder 接口 + 确定性 `DevEmbedder`(384 维
  归一化哈希向量,仅开发用)+ Gateway(内容嵌入/校验/委托)。
- 控制面 API(OpenAPI 同步):`POST /v1/memories`(幂等,201/200)、
  `GET /v1/memories/{id}`、`GET /v1/memories?query=&embedding=&namespace=
  &sensitivity=&limit=`、`DELETE /v1/memories/{id}`(If-Match CAS)。
- 测试:真实 PostgreSQL 集成(幂等/修正/租户隔离/英文 FTS/中文 trgm/
  向量排序/过滤器/墓碑/复活/保留期过期)、单元测试、handler 测试。
- 开发 PostgreSQL 镜像切换为 `pgvector/pgvector:pg18`(compose + CI 同源,
  digest 钉住)。

## 4. OCI/gVisor Provider 接入 CI

- CI(`.github/workflows/ci.yml`):显式构建 `agentos-runtime-oci` 并加入
  PATH;Linux runner 上 `go test -race ./...` 已覆盖 oci 包(linux build tag)。
- conformance 第三腿:`TestSameAgentVersionRunsOnBothProviders/oci`,由
  `AGENTOS_OCI_CONTAINERD_NAMESPACE`(+可选 `AGENTOS_OCI_IMAGE`/
  `AGENTOS_OCI_RUNTIME`)门控——containerd + runsc 沙箱主机可启用,普通
  CI 跳过;与 wasmtime 腿同构(独立进程驱动,同一断言)。

## 验证

- 构建/vet/buf lint、全部单元测试(含 race)、postgres/mcp/reference/
  control 集成套件全绿;1000 并发负载不受影响(回归通过)。
- 端到端烟测:OTLP 使能的 control 无死锁服务、trace→Tempo、log→Loki。
