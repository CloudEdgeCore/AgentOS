# v0.3 Secure Runtime: 交付文档

日期:2026-08-16 · 状态:完成

v0.3 把运行时边界从“开发可用”提升到“身份可验证、准入 fail-closed、
凭据真实、删除可传播、攻击可证伪”。六个切片全部落地并通过
构建/vet/单元/集成/race 验证。

## 1. SPIFFE X.509-SVID mTLS 身份边界(ADR-011)

- `internal/platform/spiffe`:CA + SVID 签发(ECDSA P-256,URI SAN
  `spiffe://<domain>/ns/<tenant>/worker/<instance>`;控制面
  `spiffe://<domain>/ns/system/control`)、SPIFFE ID 模式匹配、
  对端身份提取、信任束构建。
- `internal/platform/grpcx`:`ServerMTLSOptions`(RequireAndVerifyClientCert
  + TLS1.3)、`ClientMTLSOptions`、`WithSpiffeIdentity` 拦截器。
- `internal/runtime/control`:请求 claim 绑定——tenant 必须等于 SVID 租户,
  Poll 的 runtime instance 必须等于 SVID 实例;不匹配即
  `PermissionDenied`(在触碰存储之前)。
- 命令面:`agentos-svid` 生成 dev 材料(CA + 控制面 SVID + 每 worker SVID);
  `agentos-runtime-control -tls-cert/-tls-key/-trust-bundle/-spiffe-pattern`;
  reference/oci worker `-tls-cert/-tls-key/-trust-bundle`。未配置时保留
  loopback 明文 dev 模式(显式 `-dev-mode`)。
- 测试:合法 SVID 放行(NotFound 证明进入存储层)、跨租户/跨实例 SVID
  `PermissionDenied`、不可信 CA 与无证书握手失败;bufconn + 真 TLS 端到端。

## 2. OpenBao Secret Broker 参考实现(ADR-012)

- `internal/gateway/bao`:KV v2 作用域读取
  `<mount>/agentos/<tenant>/<tool>/<resource>`(resource URL 转义,
  含 `/` 的资源保持单段),`value` 键或紧凑 JSON 作为 handle,作用域
  TTL 缓存,`Ping` 健康检查;404/403/不可达/空 secret 全部 fail-closed。
- `cmd/agentos-gateway`:`-bao-addr/-bao-token/-bao-mount/-bao-namespace/
  -bao-cache-ttl`;未配置时回退 dev stub 并告警。
- 开发栈:`docker compose --profile secrets up -d`(openbao dev,
  token `bao-dev-only`,`127.0.0.1:58200`);用 `bao kv put` 播种。
- 测试:fake OpenBao(值键/JSON 数据/404/403/缓存 TTL/租户隔离/ping)+
  对真实 OpenBao 的端到端烟测(播种 → Issue → 缺失 fail-closed)。

## 3. OpenSearch 投影 + 墓碑删除传播(ADR-013)

- 规范存储在同一事务内发投影事件:`MemoryUpserted`(新写/修正;幂等重放
  不发)、`MemoryTombstoned`(CAS 墓碑);事件只带身份 + resource version。
- `internal/platform/opensearch`:最小 REST 客户端(index/get/upsert/delete,
  文档 ID URL 转义,租户作用域 `tenantId/memoryId`)。
- `internal/platform/projector`:`MemoryProjector.Apply` 按版本幂等——
  过期事件跳过、缺失记录丢弃、墓碑赢的 upsert 转删除;tombstone 删除
  传播;失败 Nak + 退避重投。
- `cmd/agentos-projector`:JetStream durable consumer
  (`agentos.events.memory.>`),启动时确保索引与 mapping。
- 开发栈:`docker compose --profile search up -d`(OpenSearch 2.17.1,
  `127.0.0.1:39200`)。
- 端到端烟测(真 Postgres + NATS + OpenSearch):PutMemory → 出箱 → 投影 →
  全文可搜;TombstoneMemory → 事件 → 索引删除,文档消失。

## 4. 签名 Agent Package + 发布准入(ADR-010)

- `internal/kernel/agentpkg`:规范 manifest(`agentos.agentpkg/v1`,digest
  钉 spec/runtime lock/tool lock/permissions/memory schema/SBOM +
  provenance),ed25519 签名/验签,`Registry` 信任键集 fail-closed。
- 发布准入(`POST /v1/agent-versions`):验签 → manifest digest → 绑定
  (manifest 签的 `name@version` 与 spec 字节必须等于本次发布);
  配置信任键时无签名拒绝(`PACKAGE_REQUIRED`),dev 模式仍验所呈包。
- 验证后的签名信封(key ID / 签名 / manifest digest)随不可变行持久化
  (迁移 000011)并随响应返回,审计可证。
- `cmd/agentos-pkg`:`genkey / sign / verify`(紧凑 JSON 保证 spec 字节
  往返稳定);控制面 `-package-trust-key` / `AGENTOS_PACKAGE_TRUST_KEYS`。
- 测试:round-trip、篡改/未知键/坏签名/坏 schema/未签名拒绝;handler
  级 fail-closed 全套;Postgres 信封持久化 + 原子性 CHECK。

## 5. 安全负向测试套件

`internal/security`(详见 [v0.3-negative-suite.md](security/v0.3-negative-suite.md)):

- **Secret leak**:执行器故意回显 handle → 结果/receipt/调用记录均无泄漏;
- **Approval binding**:已批准审批不能授权不同参数/资源/被拒决策,
  执行器计数证明不执行;
- **Tenant escape**:Tool Gateway 与 Runtime Protocol 在触碰
  store/invoker 之前拒绝异租户 claim;
- **Fencing replay**:租约失效 → recovery 接管抬高 fencing token →
  旧 token 的 heartbeat/checkpoint/transition/assignment 读取全部
  `PermissionDenied`,且无任何持久化写入(真 PostgreSQL 取证)。

## 6. Firecracker 与剩余边界

- Firecracker/microVM 保持**显式文档化边界**,不在 v0.3 交付:
  [firecracker-microvm-boundary.md](firecracker-microvm-boundary.md) 给出
  定位、实施蓝图、验收前置条件与“为什么当前边界安全”的论证。
- OCI/gVisor 仍是 runtime 侧工程基线,其加固清单
  (`runtime-provider-oci-gvisor.md` §4)是 microVM 的前置条件。
- 其余投影(cosign/OCI 镜像签名、SBOM 摄入、联邦信任、动态 secret、
  Firecracker)在对应 ADR 中标注为 projection。

## 运行清单(开发机)

```powershell
# 基础设施
docker compose --profile observability up -d   # OTel 参考栈(可选)
docker compose --profile secrets up -d         # OpenBao
docker compose --profile search up -d          # OpenSearch

# 身份材料
go run ./cmd/agentos-svid -out tmp/svid -tenant dev -worker dev-worker-1

# 控制面(示例)
go run ./cmd/agentos-control -database-url $dbUrl -dev-tenant dev `
  -package-trust-key ci-builder-1=<b64pub>    # 发布准入开
go run ./cmd/agentos-runtime-control -database-url $dbUrl -listen 127.0.0.1:9090 `
  -dev-tenant dev -dev-mode -tls-cert tmp/svid/control-cert.pem -tls-key tmp/svid/control-key.pem `
  -trust-bundle tmp/svid/ca.pem
go run ./cmd/agentos-runtime-reference -control-address 127.0.0.1:9090 `
  -tenant dev -runtime-instance-id dev-worker-1 -artifact-root tmp/artifacts -dev-mode `
  -tls-cert tmp/svid/worker-dev-worker-1-cert.pem -tls-key tmp/svid/worker-dev-worker-1-key.pem `
  -trust-bundle tmp/svid/ca.pem
go run ./cmd/agentos-gateway -database-url $dbUrl -tenant-policies deploy/dev/tenant-policies.json `
  -tenant dev -seed-dev-tools -dev-mode -bao-addr http://127.0.0.1:58200 -bao-token bao-dev-only
go run ./cmd/agentos-projector -database-url $dbUrl -nats-url nats://127.0.0.1:54222 `
  -opensearch-addr http://127.0.0.1:39200
```
